🧩 Maze Agent

A neural network predicts how hard a maze is, then an agent picks the search algorithm it expects to work best — BFS or A*.

case study
🎯 The idea

Let the agent choose

BFS and A* both solve a maze, but not equally well. On small mazes BFS is fine; on large, twisty ones A*'s heuristic saves a lot of work. I wanted a small agent that looks at a maze first, estimates the difficulty, and decides for itself, then explains why.

// pipeline
1️⃣
GenerateRandom maze (recursive backtracker) in one of 5 sizes, from 15×19 to 41×55.
2️⃣
MeasureExtract 5 features: size, wall density, start–goal distance, open cells, dead ends.
3️⃣
PredictAn MLP classifier labels it EASY, MEDIUM or HARD.
4️⃣
Decide & solveEASY → BFS, MEDIUM/HARD → A*. The agent runs it and shows its reasoning.
🧠 The model

Small, honest ML

A scikit-learn MLPClassifier with two hidden layers (16 and 8 neurons), trained for 60 epochs on 900 balanced synthetic samples with an 80/20 stratified split.

  • About 90% accuracy on the held-out test set (5 training runs: 89–92%)
  • Training log and confusion matrix shown in the UI
  • Most mistakes are MEDIUM vs HARD, the closest classes
⚠️ Limits

What I'd be upfront about

The difficulty labels come from a hand-written scoring formula, not from measured solve times. So the network learns my formula, which makes this a demo of the pipeline rather than proof that the choice is optimal.

  • State lives in server memory, so it runs as a single worker
  • Mazes are generated at fixed sizes only
🛣️ Next

What I'd improve

Replace the formula with real labels by running both algorithms on thousands of mazes and recording which expands fewer nodes.

  • Train on measured node counts instead of a formula
  • Add Dijkstra and greedy best-first to compare
  • Deploy a live demo
